# B题竞赛提交程序 v3

本目录按“本地验证”和“正式比赛”彻底分离。正式 Q3/Q4 程序均为独立单文件，不导入本地模拟器或本地 solver，也不包含真实源数据生成逻辑。

## 文件结构

- `Q1/q1_generator.py`：随机生成一组问题1测试数据。
- `Q1/q1_solver.py`：角楔半平面交、凸多边形直径、直径圆覆盖判定。
- `Q2/q2_generator.py`：随机生成一组物理相容的首测数据。
- `Q2/q2_solver.py`：安全第二检测点搜索；同时独立运行“Q1直径目标”和“Q2最小包围圆目标”作对照。
- `Q3/q3_local_simulator.py`：问题3连续随机本地压测入口。
- `Q3/q3_local_solver.py`：问题3本地 solver，被本地模拟器直接调用，不需要单独启动。
- `Q3/q3_official_solver.py`：问题3官方模拟器正式程序，独立自包含。
- `Q4/q4_local_simulator.py`：问题4连续随机本地压测入口。
- `Q4/q4_local_solver.py`：问题4本地 solver，被本地模拟器直接调用，不需要单独启动。
- `Q4/q4_official_solver.py`：问题4官方模拟器正式程序，独立自包含。

所有程序仅使用 Python 标准库，建议 Python 3.10 及以上。

本版保持四问核心算法不变，只做提交前收口：Q1支持退化定位区域；Q2对一般场景搜索示向轴两侧；Q3/Q4正式客户端增加幂等结果未知保护、下一动作时间预算和响应校验；Q4过滤同频道短基线重复复用。Q3速度参数仍采用小规模同批比较中更稳健的九点方案，没有为不足1%的样本收益冒险换参。

## Q1

进入 `Q1` 后运行：

```bash
python q1_generator.py
python q1_solver.py --input q1_input.json --output q1_result.json
```

也可直接运行 `run.bat`。生成器不指定 `--seed` 时使用系统随机种子；输出中保留 seed，出现特殊案例时可复现。

## Q2

进入 `Q2` 后运行：

```bash
python q2_generator.py
python q2_solver.py --input q2_input.json --output q2_result.json
```

也可运行 `run.bat`。求解器会在一般场景搜索首示向轴两侧，并真正执行两套选点：

1. 按问题1思路最小化最坏定位区域直径 `D`；
2. 按问题2正式思路最小化最坏最小包围圆半径 `R`。

因此对照不是“在同一个点上顺便算两个指标”。默认比较 600、700、800、900、1000 m 基线，并在安全弧上细化。内层连续示向度的最坏值采用有限网格与局部细化数值近似；输出明确标记为不具有连续全域最优证书。

## Q3 本地连续压测

只启动一个程序：

```bash
cd Q3
python q3_local_simulator.py
```

程序会询问测试局数，例如输入 `5000`。本地模拟器在同一进程中逐局随机生成 10–16 个全向源，并调用 `q3_local_solver.py`，无需再开第二个终端。结束后自动保存一个 JSON 文件到 `results/`。

固定复现实验可用：

```bash
python q3_local_simulator.py --loops 5000 --seed 20260911
```

## Q4 本地连续压测

同样只启动一个程序：

```bash
cd Q4
python q4_local_simulator.py
```

每局随机生成 10–16 个混合源，位置、频道、有效接收半径、定向源数量和定向方向均随机。结束后自动保存 JSON 到 `results/`。

## Q3 / Q4 官方模拟器

正式程序不需要改文件名、日志名或轮次。每次测试使用同一条启动命令即可：

```bash
python q3_official_solver.py
```

或

```bash
python q4_official_solver.py
```

程序自动等待 `http://127.0.0.1:2026` 接口开放，日志文件名自动按时间生成。

### 参赛队号

参赛队号没有写死在任何源程序中。可以每次启动时按提示输入，也可以在 PowerShell 当前会话中只设置一次：

```powershell
$env:CUMCM_ROBOT_ID="你的参赛队号"
```

之后 Q3/Q4 每局都直接运行固定命令，不再输入队号。提交支撑材料前不要把真实队号写进 `.py` 或 `.bat`。

程序自己的 JSONL 记录会把 `robot_id` 写成 `<TEAM_ID>`，避免支撑材料误带队号。官方模拟器生成的加密正式日志仍需按竞赛要求原文件名导出，不要修改。

## 正式接口中已经处理的稳定性细节

- 请求严格串行，不并发发送不同动作；
- 每个新动作自动生成新的 `request_id`；
- 网络超时或连接中断重试同一个动作时，完整复用原请求内容和原 `request_id`；
- 动作在重试后结果仍未知时，禁止生成新动作或用新ID发送 `/exit`；
- 同时检查 HTTP 状态和 `accepted`；
- `/enter` 后读取实际 `remaining_real_duration_s`，不把 1200 秒写死；
- `/clear` 不改变当前测向频道；
- 检测的 5 秒只由模拟器推进虚拟时间，程序不会额外 `sleep(5)`；
- 发动作前按移动、检测、换台或清除的最坏增量检查虚拟时间，并为正常退出预留现实时间；
- 正式程序不访问任何本地真值、随机源列表或本地测试数据。

## 当前算法口径

- Q1：有界误差角楔交 + 半平面交 + 旋转卡壳直径 + 直径圆覆盖判定。
- Q2：统一接收安全域内，以所有物理可行第二示向度下的最坏 MEC 半径为主目标，直径和面积为辅助；另独立运行 Q1 直径目标作对照。
- Q3：原点 + 8 外围点连续覆盖，全向源集合成员定位，MEC 19.8 m 清除证书，小侧移主动定位、停靠点测向复用和顺路调度。
- Q4：中心 + 8 内圈 + 16 外圈共25点方向覆盖，普通无信号不裁剪；发现后采用正锚点成对探测，双无信号只在认证距离内做安全半平面裁剪，MEC 19.8 m 后认证清除；机会复用要求与同频道最近检测点至少相距25 m。

Q3/Q4题设物理示向误差为 ±1°；程序使用1.0051°的保守计算角楔，其中0.005°用于两位小数输出量化保护，0.0001°用于数值裕量。这是外包络保护，不是把题设误差改成1.0051°。

## Q3时间构成与参数选择

同批固定种子小样本中，现行Q3约78.7%的虚拟时间来自移动，约16.5%来自检测，换台约3.1%，清除约1.7%。九点固定覆盖骨架约6.0 km，但发现后的定位、清除及返回覆盖路线会产生额外绕行。减少外围点会使外围半径超过999 m，失去大量停靠点保证接收复用，实测反而更慢；600 m插入阈值和0.1R侧移也比附近候选更稳定。因此本版保留原参数，不宣称全局最优，只称为所比较有限配置中的稳健选择。

## 赛前建议

Q3、Q4 正式测试各只有3次机会。正式测试前先用官方“演练测试”跑若干局，确认本机 Python、端口、网络和程序日志均正常。论文中的正式测试案例编码来自模拟器界面，不由 HTTP API 返回。

## 本地批量测试统计
Q3、Q4本地模拟器会同时报告“逐局等权平均每源耗时”和“合并源数加权每源耗时”，并给出移动、检测、换台、清除四部分时间分解。论文跨局主表应统一使用前者；单次正式测试仍按该局总虚拟时间除以该局成功清除数。上述统计同时写入结果JSON。

论文与最终程序的同步事项见 `论文同步修改清单.md`。本地模拟结果不能写成官方演练或正式成绩；正式结果必须由用户在官方模拟器运行后填入。
