# 源码研读课　从一条公式追到一个分支

本课是前七课的**解答册**，不是新算法。先合上源码写出一般模型和本题模型，再从入口往下追；函数名不等于证明。表中行号以仓库 `source/` 的当前版本为准。本地 Q3/Q4 的策略部分与正式文件相同；正式文件后面还接 HTTP 客户端，须另读协议附录。

## 8.1　读代码的四个问题

对任意一行，先找到所在函数，回答：**输入是什么；这一行改变了什么状态；它实现哪一个集合、公式或控制规则；如果它的条件不成立会发生什么。**例如 Q4 `if r1!='no_signal':return` 不是随意省掉第二次测量：第一站若收到示向就已有新的正锚点，继续用旧锚点的第二测点已不是原来那一轮的证明。

| 公式或不变量 | 程序变量 | 每次更新后要保持什么 |
|---|---|---|
| $g_i\in P_i$ | `Track.poly` | 真实源始终在候选外包络中；空集是错误信号 |
| $P_i\subseteq B(c_i,r_i)$ | `center,radius` | 半径复核包括所有顶点；凸多边形内点也被圆覆盖 |
| $\|q-c_i\|+r_i\le19.8<20$ | `nearest_certified_clear` / `nearest_clear` | 发清除前可证明每个候选位置都在阈值内 |
| $\Omega\subseteq\bigcup_s B(s,999)$ | Q3 `scans`,`covers_arena` | 只有已访问并扫描的站位能用于完成证书 |
| $n\cdot(a-g)\ge0$ | Q4 `anchor` | 只能用真实收到过信号的站位作锚点 |

**四条主调用链。** Q1：`main → solve_localization → _observation/_wedge → intersect_halfplanes → _finite_result → polygon_diameter`。Q2：`main → solve_case → optimize_fixed_baseline → safe_angle_limit/safety → robust_quality → evaluate → post_region → polygon_metrics`，随后 `final_quality` 用更密采样复评。Q3：`run_case → Strategy.run → _scan/_choose/_serve → _observe/_clear`，其中 `_observe` 调用几何函数。Q4：`run_case → Strategy.run → _scan_site/_choose_insert/_service → _pair_round → _observe/_dual_negative`。

## 8.2　问题一：一道观测题怎么落到行号

**已知** $(s_i,\widehat\theta_i)$；**未知** $g$；**要求** $P=\bigcap_iW_i$ 的直径及指定直径圆的覆盖性。`_wedge` 第 257–265 行把每个 $W_i$ 改写成两个闭半平面：第 259 行计算 $\theta_i\pm\delta$，260–261 行构造法向量，265 行令偏移量为 $n\cdot s_i$；第 262–264 行仅在零角误差时补“向前”的方向条件。

第 268–280 行是数据到几何的转换：269–271 行拒绝不合理角误差，272–274 行标准化观测并拒绝空列表，275 行展平所有半平面，276 行求交，277–280 行把可追溯输入连同结果返回。半平面 `HalfPlane.residual` 的正号意为越出可行一侧；`_normalise` 第 43–59 行统一单位法向量以比较平行约束；`_ordered` 第 73–87 行按边界方向排序并留下同向更紧的一条；`_intersection` 第 90–97 行求两边界交点，行列式太小则不强算。

`intersect_halfplanes` 第 201–237 行维护一个双端队列。206–211 行逐条放入约束并弹出两端已被新约束排除的交点；212–215 行处理首尾闭合；217–225 行求候选顶点，并用**所有**原约束重验；228–237 行没有得到可靠有限图形时分别报告空、无界或不确定。第 203 行 `del include_circle` 说明该函数**没有**把半径 1800 m 的真实目标圆精确加入半平面交；不能从参数名字推断它加了圆。

`_finite_result` 第 184–198 行先处理点、段、面三种维数，再由 `polygon_diameter` 第 160–181 行求凸包最远点对。第 170–180 行中 `j` 指向当前边的对踵候选，叉积比较的是两个顶点到有向边的面积尺度；旋转卡壳扫描时指针只前进。第 192–198 行以最远对中点、半距离画**题目指定的圆**，再逐顶点查最远距离。`farthest <= radius + EPS` 才能说它覆盖；这不是在求最小包围圆。

**口试自查。** 如果只给一个角楔，为什么不输出有限直径？因为它向前延伸无界；程序可能报告 `unbounded`。如果评委问“目标明明在圆域内”，说明这是题设与当前 Q1 独立程序计算对象的区别，再解释需要额外加入圆域交，不能把两种结果混为一谈。

## 8.3　问题二：先保证接收，再比较候选点

一般模型的决策顺序是 $s$ 在前，可能收到的读数 $y$ 在后：

$$
F_1=\Omega\cap B(s_1,1500)\cap W(s_1,\widehat\theta_1),\quad
F_2(s,y)=F_1\cap B(s,1500)\cap W(s,y),
$$

$$
S_{\rm safe}=\{s:\forall g\in F_1,\ \|s-g\|\le1000\},\qquad
\min_{s\in S_{\rm safe}}\max_{y:F_2(s,y)\ne\varnothing}R(F_2(s,y)).
$$

第一个 $\forall$ 给保守二次接收保证；第二式的内层 $\max$ 是尚未知道的**可实现**读数。最小包围圆 $R$ 是定位质量指标，不是时间目标。实际程序在有限基线与偏角上搜索，内层读数也只离散加局部细化；因此报告值是数值近似。

| 行号 `source/Q2/q2_solver.py` | 数学动作 | 当场能回答的“为什么” |
|---|---|---|
| 57–60 | `local_to_world` 旋转局部沿首示向/侧向坐标 | 首站不一定在原点、示向不一定为 0° |
| 63–77 | 极值可在扇形半径端点或反向投影方向；求最大距离平方 | 把“所有可能源”压成有限的极值检查 |
| 80–111 | `safe_full_information` 与默认 `safe_uniform_1000`，再求安全偏角上界 | 默认用对所有 $F_1$ 的 1000 m 保证；二者不是同一站域 |
| 114–178 | 外切圆盘多边形，半平面裁剪、角楔、首观测集合 | 圆盘的外近似不意外删掉真源；5 m 内孔被省略会放松集合 |
| 186–236 | 两/三点支撑圆，逐点增量求最小包围圆并复核所有点 | 三角形钝角与锐角可能由不同支撑点决定 |
| 278–285 | 候选站位处加 1500 m 物理盘和第二角楔 | 没有把与读数不相容的源读数任意拼接 |
| 318–399 | `evaluate(y)`、360° 粗采、局部峰值黄金分割、分别取 $R,D,A$ 的最大 | 黄金分割只是局部细化；没有证明整个质量函数单峰 |
| 408–469 | 固定 $L$ 两侧偏角搜索，用 `safe_*` 过滤，再选最小分数 | 左右在任意首站不一定对称；网格只给采样最优 |
| 481–519 | 在若干基线分别优化 $D/R$，更密复评并写 JSON | 比较“各自优化后的方案”，不偷换成同一点的两种指标 |

**逐句追第 318–350 行。** `evaluate` 把第二读数模 360° 缓存；`post_region` 与第二角楔求交；空集表示该读数在近似模型中不可能；非空才算直径、包围圆、面积。`records` 收集**评估过**的读数；`coarse` 保留等间隔下标供寻找局部峰。不能把 `max(records)` 解读为连续 $y$ 的上确界。

**自测题及答案。** 已固定安全站位 $s$，只有 $y_1,y_2$ 两种可能读数，后验包围圆半径为 8、12 m。该站最坏质量是 12 m；另一站是 10、11 m，则极小极大选另一站，值 11 m。先对每一站取最大再在站间取最小；颠倒量词会假装事先知道读数。

## 8.4　问题三：从状态变量解释每个决定

把这一问拆成**发现可行性、单源位置估计、清除证书、时间启发式**四个模型。已经发现某频道并不等于覆盖了全部未知频道；预计绕路短也不等于安全清除。

| 行号 `source/Q3/q3_local_solver.py` | 输入、动作、更新与前提 |
|---|---|
| 9–23 | `DELTA` 将真实 1°、报告取整及数值裕度分开；向量运算给后面法向量、距离与位置提供共同单位（米/弧度） |
| 25–61 | 凸包、`clip`、外切 48 边形；裁剪时 `b` 略向外放宽以保护包含性 |
| 63–99 | 正读数用两个角边与一个轴向上界更新；全向无信号才可删保证接收盘，但保留其剩余部分的凸包外近似 |
| 109–154 | MEC 由 1、2、3 个边界点生成，终点再审全部顶点；`nearest_certified_clear` 投影到 $B(c,19.8-r)$ 的最近点 |
| 156–222 | 圆盘覆盖目标圆域用连续圆弧区间检验；`ring_sites(8)` 给原点后的八站，`rotate` 默认关闭 |
| 229–265 | `Config` 区分默认策略与关闭的研究分支；每个频道 `Track` 保存状态、候选多边形、负观测、圆与最近正读数 |
| 281–311 | `_observe` 先处理接口反馈，再按 `no_signal/near/direction` 更新；无信号只在 `FOUND` 且允许负更新时裁剪；空集即停止 |
| 313–326 | `_clear` 的成功结果才计数；号称认证清除却失败会抛错，不能默默吞掉反例 |
| 332–361 | `_certify_and_prune` 用已发现 16 个或已扫圆盘覆盖宣告其余未知频道不存在；`_scan` 在该站逐个检测未知频道 |
| 371–394 | `_make_plan` 默认用固定八站；旋转候选方案存在于代码但关闭，不能报告其改善效果 |
| 396–430 | `_tracking_point` 在保证范围内选偏侧测点；`_serve` 不断观测直至半径满足 19.8 m，失败即停止 |
| 454–498 | `_choose` 的绕路评分和 600 m 阈值只安排时序；`run` 在每次动作之后重新判定下一步 |

**把第 281–311 行读成一张状态表。** `UNKNOWN + direction → FOUND`，正读数裁剪角楔并重算圆；`FOUND + no_signal → FOUND`，全向情况下可作安全外近似删盘；`UNKNOWN/FOUND + near → CLEARED`，由接口的 5 m 近距反馈允许直接清除。`Track.negatives` 保存此前阴性站位，等首次正观测后可以继续施加；`measurements` 只数有效示向，`virtual_time` 用模拟器返回值而非自行估算。

**为何 19.8 有效。** 若 `poly` 始终包含真源，且 `mec(poly)=(c,r)`，对 `q=nearest_certified_clear(p,c,r)` 有 $\|q-c\|\le19.8-r$，所以对任意 $g\in P$，$\|q-g\|\le\|q-c\|+\|c-g\|\le19.8<20$。这是以集合包含不变量为前提的条件证明。第 304–308 行选择更小的**经过全部顶点复核的圆**，因此不单凭理论三角形半径更新清除。

**为何不是 TSP 最优。** 设当前点 $p$、下一覆盖站 $s$、已知频道候选中心 $c$。第 463 行算 $\Delta=d(p,c)+d(c,s)-d(p,s)$，即把一次绕经 $c$ 插入旧边 $p\to s$ 的增量；465 行再加 $r$ 作不确定性惩罚。真实服务可能要多次观测且任务未来才出现，这个评分只是在线启发式。`run` 第 483–487 行按最新状态选择服务或前进；没有离线城市全集，更没有最短路线证明。

## 8.5　问题四：把盲区条件映射到两种正负反馈

把源位置 $g$、未知单位朝向 $n$ 一起视为隐状态；一次正观测意味着 $\|p-g\|\le\rho$ 且 $n\cdot(p-g)\ge0$，一次阴性只能推出两条件至少一个失效。**Q3 的删盘公式绝不能沿用到 Q4 单次阴性。**

| 行号 `source/Q4/q4_local_solver.py` | 数据与数学意义 |
|---|---|
| 8–13 | 物理半角 1°、放宽半角 1.0051°、清除裕度 19.8、成对系数 0.5 和 0.05 |
| 39–47 | 外切 64 边形初始化；正读数把位置多边形裁到角楔与轴向上界 |
| 58–83 | 求并复核 MEC；认证动作点仍是距当前点最近的 $B(c,19.8-r)$ 内点 |
| 85–89 | 原点、八个 995 m 内环站和十六个 1838 m 外环站；`order` 只改外环访问顺序 |
| 92–112 | `anchor` 是**最近一次正观测站**，`last` 是最近测站，`U` 是锚点到源的上界；正观测才刷新锚点 |
| 121–129 | `no_signal` 不裁 `poly`；`near` 触发直接清除；`direction` 交新角楔 |
| 131–154 | 达源数上界或完成预置覆盖路线后才结束未知频道扫描；机会复测已知频道不替代完整扫描 |
| 155–169 | 两负且满足已证几何条件，才裁 $u\cdot(g-a)\le0.5U$；先正或近则本轮直接返回 |
| 170–187 | 半径够小清除，否则至多九轮成对测量；插入评分是绕路加半径 |
| 188–208 | `run` 更新发现/服务/覆盖状态直至结束，再按真实接口时间输出汇总 |

**逐行口述 `_pair_round`（159–169）。** 160–161 行取目标轨迹并检查必须有正锚点。162 行取锚点读数的正交单位基 $(u,v)$ 及源距上界 $U$。163 行构造 $q_\pm=a+0.5Uu\pm0.05Uv$。164 行先去近的一点以节约路程；它不改变两点的几何证书。165 行收第一次反馈，166 行若已清除或得到正读数就结束本轮；167 行在第一次阴性后收第二次反馈，168 行再作相同判断；169 行仅双负时调用保守半平面裁剪。`_dual_negative` 第 156 行裁远侧、第 158 行把 $U$ 至多更新为 $0.5U/\cos\delta$ 并重算 MEC；因此它改变的是位置上界，不能说它直接识别了发射朝向。

**计算题与答案。** 取 $U=1000$ m，$a=(0,0)$、$u=(1,0)$、$v=(0,1)$。两点为 $(500,50)$、$(500,-50)$。如果两点都返回阴性，且正锚点、全部候选位置到两测点距离小于 1000 m 与跨楔条件均已证明，则保留 $x\le500$ m；新的上界不大于 $500/\cos(1.0051^\circ)\approx500.077$ m。若第一点已返回正示向，不运行旧锚点的第二点，更不能使用双负式。

## 8.6　正式客户端、生成器与批处理：源码全貌

四个 `source/Q1`、`source/Q2` 的生成器产生测试输入，求解器负责模型计算；生成器中的随机数用于造例，不能被说成测向误差的概率模型。Q3/Q4 的 `q*_local_simulator.py` 生成隐藏真值并模拟 `measure/clear`；策略代码只接收动作反馈，不读取隐藏真值。`q*_official_solver.py` 的前半段复用相同策略，后半段 `OfficialClient` 管理 HTTP 请求、重试、日志、`/enter`、`/exit` 和截止时间；它属于通信与异常处理，不提供新的几何保证。六个 `.bat` 脚本只是选择 Python 文件及参数的入口。

完整函数级索引和各异常分支见旧版 [源码地图](../book/05_源码地图与逐段精读.md)。遇到评委指定的任意一行，先在本课定位其**状态/公式所在段**，再看上一行输入与下一行用途；对没有执行的研究分支如 `rotate`、`prune`、`speculative_r`，按 `Config()` 默认值说明其没有参与主策略。若被问到暂未覆盖的 Python 语法，先解释赋值、推导式、切片、异常、装饰器的语言作用，切勿把语法动作误说成数学定理。

## 8.7　闭卷验收的四个短题及标准答案

1. **Q1。** 最远点对距离 $D$ 能否保证以该对为直径的圆覆盖？**答：**不能；等边三角形任一边为直径时第三顶点在圆外。Q1 逐顶点检查，而清除问题采用 MEC。
2. **Q2。** 报告的 $55.82$ m 是什么量？**答：**在指定输入、站位与有限采样/细化参数下，最坏已评估第二读数的后验最小包围圆半径近似值；不是连续最优下界，也不是 20 m 清除保证。
3. **Q3。** 九站环和插入评分分别证明什么？**答：**圆盘覆盖加逐频道扫描在相应前提下支持找齐；评分只决定何时绕路服务，不证明时间最短或清除安全。
4. **Q4。** 为什么阴性后 `poly` 原样返回却双阴性后能裁？**答：**单点可能位于源的背面。两点在保证接收距离内且其连线跨过正锚点到远端候选源的射线时，双阴性会与正锚点的朝向条件矛盾，才允许裁远半边。
