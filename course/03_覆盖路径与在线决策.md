# 第 5 课　覆盖、巡回与在线插入：三个不同的优化模型

一个服务者要在若干地点完成任务，表面上像一个“规划路线”的问题，实际上包含三个相继的决定：**访问哪些地点**、**按什么次序访问**、**执行中出现新任务时怎么办**。它们分别对应集合覆盖、旅行商路线和在线插入。每换一次模型，未知量、约束和能证明的结论也随之改变。本课从有限的标准问题学起，到章末才把覆盖对象换成干扰源的连续位置域。

**预备知识。** 会计算集合的并集、平面两点距离以及一条路线的总长度即可。本课不以计算复杂性证明为入门门槛。

**本课应达到的程度。** 闭卷写出下面三组模型的输入、未知量、约束、目标及算法；手算例 5.1—5.4；把式 (5.1)—(5.8) 中适用的变量逐项代换到 Q3/Q4；能指出代码中的评分是模型的哪一部分，以及哪些部分只是人为选择。这里不要求证明一般 TSP 的复杂性，也不把数值试跑误认为最优证明。

**本课公式索引。** 有限覆盖用 (5.1)；巡回目标用 (5.3)；一条边的插入增量用 (5.4)；在线状态和时间用 (5.5)—(5.6)；当前任务评分用 (5.7)。章末应用会从 (5.1) 推出连续覆盖条件 (5.8)，再把 (5.4) 代入源码的 `detour`。

## 5.1　覆盖：哪些地点值得去

### 5.1.1　从一个完整问题出发

某软件项目要同时具备 C、C++、Ruby、Python 和 Java 五种技能，团队人数越少越好。候选者及其技能如下。该数据取自 Trevisan 的课程讲义 *Lecture 4: TSP and Set Cover* 中的程序员团队例；这里的叙述、推导和练习由本教材重写。[原讲义](https://theory.stanford.edu/~trevisan/cs261/lecture04.pdf)

| 人员 | C | C++ | Ruby | Python | Java |
|---|:---:|:---:|:---:|:---:|:---:|
| Andrea | ✓ | ✓ |  |  |  |
| Ben |  | ✓ |  |  | ✓ |
| Lisa |  | ✓ | ✓ | ✓ |  |
| Mark | ✓ |  |  |  | ✓ |

请暂时不想算法，先问：一个答案是什么？答案是被选中的人员名单；验证答案是否可行，只需检查名单中的技能并集是否为五种技能的全集。

**定义 5.1（有限集合覆盖）。** 给定有限需求全集 $U=\{u_1,\ldots,u_n\}$、候选集合 $S_1,\ldots,S_m\subseteq U$ 及其非负成本 $c_i$。决策变量 $x_i=1$ 表示选择候选 $i$。输入是这些集合和成本，输出是一个 0—1 向量。模型为

$$
\min_{x\in\{0,1\}^m}\sum_{i=1}^m c_ix_i
\quad\text{使得}\quad
\sum_{i:u_j\in S_i}x_i\ge 1\quad(j=1,\ldots,n). \tag{5.1}
$$

约束说的是“每一项需求至少被一名选中的候选满足”；它与 $\bigcup_{i:x_i=1}S_i=U$ 等价。人数最少时取 $c_i=1$。**可行**只要求全部约束成立；**最优**还要求在所有可行向量中成本最低。先明确这两个词，后面才能正确评价贪心法。

### 5.1.2　例 5.1：完整求解四人覆盖问题

代入模型，Ruby 和 Python 只能由 Lisa 覆盖，所以必取 $x_L=1$。此时还缺 C 和 Java；Mark 同时提供这两项，故 $x_M=1$，其余取 0 是可行解，目标值 2。没有一个人覆盖五项需求，故目标值至少为 2；由下界和已构造的上界可知最优值恰为 2。这里先由**需求约束**缩小选择，再分别证明可行性与最优性。

若先选 Andrea，尚缺 Ruby、Python、Java。Lisa 提供前两项，而 Ben 或 Mark 才提供 Java，于是这条选择路径会选出三个人。可见选择顺序会影响构造过程；一个“看起来能补需求”的决定未必产生最优解。

### 5.1.3　候选很多时的贪心方法

**算法 5.1（单位成本贪心覆盖）。** 初始化未覆盖集 $W_0=U$，已选集合为空；只要 $W_t\ne\varnothing$，选择新增覆盖最多的候选 $i_t$，然后更新

$$
i_t\in\arg\max_{i:x_i=0}|S_i\cap W_t|,
\qquad W_{t+1}=W_t\setminus S_{i_t}. \tag{5.2}
$$

不同成本时常以 $|S_i\cap W_t|/c_i$ 排序，但须先规定 $c_i>0$ 与并列规则。若每个尚未覆盖元素均不属于任何剩余候选，算法应报告不可行，不能无限循环。原例第一轮 Lisa 增加三项技能，第二轮 Mark 补齐两项，得到 2 人；只有例 5.1 的独立下界证明了此例最优，贪心停止本身没有这个含义。

**正确性与界限。** 更新始终保持“不在 $W_t$ 中的需求已有选中集合覆盖”。若最终 $W_t=\varnothing$，则所得 $x$ 满足式 (5.1) 的全部约束，这是**可行性证书**。一般情况下贪心并不保证最少人数；需要额外证明或符合前提的近似界，才可谈性能保证。

| 本节对象 | 内容 |
|---|---|
| 输入 | 有限需求全集、每个候选能覆盖的需求、选择成本 |
| 输出 | 被选中的候选集合 |
| 必须满足 | 并集覆盖全集 |
| 贪心规则 | 每轮优先增加当前尚未覆盖的需求 |
| 在一般实例中的界限 | 可行性与最优性是两种不同结论 |

## 5.2　路线：已经知道要去哪里，怎样走

上一节只选人员，没有“先找谁”的路程。现在假定需要访问的地点已经给出，才能建立第二个模型。给定城市 $V=\{s,v_1,\ldots,v_k\}$、对称边权 $d$，闭合旅行商问题要求从 $s$ 出发、各城市访问一次、最后回 $s$。决策量是排列 $\pi$，目标函数为

$$
\min_{\pi\text{ 是 }v_1,\ldots,v_k\text{ 的排列}}
\bigl[d(s,\pi_1)+\sum_{j=1}^{k-1}d(\pi_j,\pi_{j+1})+d(\pi_k,s)\bigr]. \tag{5.3}
$$

有起点但不要求返回时应删去末项，得到**开放路径**；正在执行的路线甚至可能随观测改变。下述手算先只讨论式 (5.3)，不提前带入赛题。

### 5.2.1　例 5.2：四个地点的精确枚举

Lippman 的开放教材 *Math in Society* 的图论章节给出四点巡回及最近邻比较。该例的边权为一般路费，**不是欧氏距离**；例如 $d(B,C)=13>d(B,A)+d(A,C)=6$。[教材入口](https://www.opentextbookstore.com/mathinsociety/)

| 起点/终点 | A | B | C | D |
|---|---:|---:|---:|---:|
| A | 0 | 4 | 2 | 1 |
| B | 4 | 0 | 13 | 9 |
| C | 2 | 13 | 0 | 8 |
| D | 1 | 9 | 8 | 0 |

从 A 出发，访问 B、C、D 各一次，最后返回 A。输入是上表和起点，未知量是 B、C、D 的排列。由于边权对称，反向巡回费用相同，固定起点后只须比三条：

| 巡回 | 算式 | 总成本 |
|---|---|---:|
| A–B–C–D–A | $4+13+8+1$ | 26 |
| A–B–D–C–A | $4+9+8+2$ | 23 |
| A–C–B–D–A | $2+13+9+1$ | 25 |

所以最优成本 23。这里的“最优”来自穷尽比较；固定 $n$ 点时的枚举量约为 $(n-1)!/2$，不能把四点时的便利当成大规模算法。

**例 5.3（最近邻启发式）。** 每次从当前位置去尚未访问者中成本最低的地点。A 的最近未访点是 D（成本 1），D 接着选 C（8），C 只能选 B（13），最后回 A（4），总成本 26。它符合全部访问约束，却在本例中比最优值 23 多 3。它的**输入**与精确模型相同，**输出**是按局部规则构造的一条可行路线；不能把二者的“问题模型”与“求解方法”混为一谈。

### 5.2.2　插入：路线存在时才出现的新任务

设已有一段路 $a\to b$，新任务在 $x$。把这段改成 $a\to x\to b$，其他段不变，增加成本为

$$
\Delta(a,x,b)=d(a,x)+d(x,b)-d(a,b). \tag{5.4}
$$

它只说明**给定插入位置**的边长变化。枚举该路线的全部边，取增量最小处，得到新任务对于这条既有路线的最佳插入位置；这并未遍历所有可能的全局路线。闭合巡回要考虑返程边，开放路径还要考虑末端追加。

**例 5.4（最便宜插入位置）。** 在例 5.2 的成本表里，已有 A–C–D–A，费用 $2+8+1=11$，插入 B：

| 替换边 | 增量 $\Delta$ | 新巡回费用 |
|---|---:|---:|
| A–C | $4+13-2=15$ | 26 |
| C–D | $13+9-8=14$ | 25 |
| D–A | $9+4-1=12$ | 23 |

选择 D–A，得到成本 23。这里恰与全局最优相同是本例事实，不能由式 (5.4) 保证一般情形也是如此。式 (5.4) 的三个长度与新旧路线总长度相减相等，是**给定旧路线的精确增量**；“只比这三条边就已得到全局最短巡回”则是错误结论。

欧氏距离满足三角不等式，故式 (5.4) 的增量非负；例 5.2 的一般边权没有这个前提，不应把该性质拿来解释其所有数字。

**算法名称辨析。** 最近邻比较的是“当前位置到哪里最近”；最近插入先选靠既有路线近的未访点；最便宜插入比较候选点与插入边组合的增量；2-opt 在已有完整路线中尝试替换两条边。它们不是同一算法，Q3/Q4 也没有实现一个通用的精确 TSP 求解器。插入法的标准算法分类可参见 Cook 等的 *Combinatorial Optimization* 第 7.2 节。[章节入口](https://www.math.uwaterloo.ca/tsp/book/index.html)

## 5.3　在线决策：未来任务尚不知道

经典 TSP 的所有城市在求解前给出。在线任务可能在执行中才出现，已经走过的路不能撤销。下面只建立一个**一般在线插入问题**：服务者按基础路线巡查，观察到新任务后决定现在插入服务还是继续巡查。状态不是一个固定城市排列；决策必须只用当时已经获得的信息。

**状态与动作。** 在第 $t$ 次决策时，信息状态为

$$
I_t=(p_t,s_t,\mathcal J_t,\mathcal H_t),\quad
a_t\in\{\text{继续巡查},\text{服务已发现任务 }i\in\mathcal J_t\}. \tag{5.5}
$$

$p_t$ 为当前位置，$s_t$ 为计划下一站，$\mathcal J_t$ 是目前已发现而未服务的任务，$\mathcal H_t$ 是截至此时的观测史。未来任务没有出现在 $\mathcal J_t$ 中。任务完成或得到新观测后，状态按反馈更新，再作下一次决定。

**时间目标。** 若路程为 $L$、速度为 $v$、测量/切换/成功服务/失败服务次数分别为 $N_m,N_s,N_+,N_-$，单次运行的总时间可写作

$$
T=L/v+\tau_mN_m+\tau_sN_s+\tau_+N_++\tau_-N_-. \tag{5.6}
$$

这是**评价已发生的一次运行**的时间分解；若考虑未知未来，必须另外指定随机分布、最坏情形或竞争基准才有相应的最优化模型。此处并未给出未来任务分布，因此不能声称下面的局部规则在 (5.6) 上具有期望或最坏最优性。

设当前位置 $p$、下一巡查站 $s$，已发现任务的估计位置 $c$。绕经 $c$ 的行程增量是

$$
\Delta_{\rm route}=d(p,c)+d(c,s)-d(p,s).
$$

真正服务可能需要在 $c$ 附近多次检测，所以该式只计算“假设绕经估计中心”的额外**路程**。可在它上面加对不确定性的惩罚，再用阈值作局部决定；惩罚和阈值来自策略设计，不能说是由路程模型唯一推导出来的。

### 5.3.1　从标准插入式到一条启发式决策规则

在式 (5.4) 中代入 $a=p,b=s,x=c$，得到上一式。欧氏距离满足三角不等式，故绕行量非负；除以 $v$ 是**绕经估计中心的行走时间增量**，不包含服务过程中的多次测量与未来新增任务。

若任务 $i$ 的位置由圆心 $c_i$、不确定半径 $r_i$ 概括，给定权重 $\lambda\ge0$、阈值 $h$，规则为

$$
H_i=\underbrace{d(p,c_i)+d(c_i,s)-d(p,s)}_{\text{插入路程}}
      +\underbrace{\lambda r_i}_{\text{人为设计的不确定性惩罚}},
\quad i^*=\arg\min_{i\in\mathcal J_t}H_i;
\quad H_{i^*}\le h\text{ 时先服务 }i^*. \tag{5.7}
$$

式 (5.7) 的前半来自边替换，后半是策略设计，不能把 $\lambda r_i$ 说成必走路程。$h$ 是行动门槛，不是接收距离或清除阈值。**完整手算：**取欧氏坐标 $p=(0,0),s=(6,0),c=(3,4)$，两段绕行各长 5，直行长 6，插入增量为 4。取 $r=2,\lambda=1,h=5$，评分 6，大于门槛，继续去 $s$；若只把 $h$ 改为 7，则本轮插入。几何增量始终为 4，两种决定都没有证明全局最优。

下一节才代入 Q3/Q4 的具体数据。式 (5.7) 是一种**策略类**，不是自动保证覆盖、定位或最短时间的定理。它只有在任务已有估计中心、半径等信息时才可计算；若没有下一站 $s$，应另定义末端服务规则，不能机械使用带 $d(c,s)$ 的式子。

### 5.3.2　评价一条策略时分开三件事

1. **覆盖完成：** 是否已经巡视了足以接触每个可能目标的站点？需要覆盖证书。
2. **服务安全：** 发出清除指令前，所有仍可能的目标位置是否都在清除范围内？需要距离证书。
3. **效率：** 在满足前两项的前提下，路线和动作怎样减少时间？这里可以使用启发式与实验对照。

同一个策略可以有前两项的条件性保证，而对第三项只给数值观察；不应以几局短测的时间优势替代覆盖证明。

## 5.5　章末应用：Q3/Q4 中的三个决定

现在才使用赛题。目标位于半径 1800 m 的区域内，设备在站位检测并按频道服务。此处的**覆盖对象**是连续的可能目标位置，不是有限的“程序员技能”；**服务任务**只能在观测后出现，也没有预先知道的源坐标。标准模型因此成为设计思路，而不是一套可以直接套用的标准 TSP 解。

### 应用 A：Q3 如何证明“找齐”

Q3 的全向源在一定距离内可接收。若每个目标位置都在至少一个已测站点的保证接收圆盘内，并且在这些站点轮询相应未知频道，未发现的源才可在条件下判为不存在。形式上是连续集合覆盖：

$$
\Omega\subseteq\bigcup_{s\in S} B(s,r_0). \tag{5.8}
$$

其中 $\Omega$ 是目标位置域，代码用保守半径 $r_0=999$ m。`source/Q3/q3_local_solver.py` 的 `ring_sites`（207 行）产生默认八个环站；入口先在原点扫描，`covers_arena`（187 行）用目标域边界与暴露圆弧的区间关系检查**连续区域**，而非仅检查网格点。`_certify_and_prune`（335 行）在已知 16 个源或覆盖完成后更新状态。覆盖公式是安全结论的条件；站点的访问次序另归路线安排。

**把默认九站亲手算出来。** 这是上一段的缺失步骤。设目标圆半径 $D=1800$，中心站为 $o=0$，外环有 $m=8$ 个等角站 $s_k=a(\cos(2\pi k/m),\sin(2\pi k/m))$，实际用 999 m 作保证半径。任何 $g$ 只需考虑与它方位最近的环站，夹角 $\phi$ 满足 $|\phi|\le\pi/8$。中心站已覆盖 $r=\|g\|\le999$；对余下的 $999\le r\le1800$，余弦定理给最近环站的距离上界

$$
\|g-s_k\|^2\le f(r)=r^2+a^2-2ra\cos(\pi/8).
$$

$f(r)$ 是关于 $r$ 的凸二次函数，所以在区间 $[999,1800]$ 的最大值出现在两个端点之一。`ring_sites` 第 210 行先按目标边界距环站为 995 m 解二次式，取较小的根再加 1 m：

$$
a=1800\cos(\pi/8)-\sqrt{995^2-[1800\sin(\pi/8)]^2}+1
\approx945.9734\ \mathrm m.
$$

代回端点有 $\sqrt{f(999)}\approx382.9931$ m，$\sqrt{f(1800)}\approx994.2786$ m，二者都小于 999 m。由端点最大性质及中心盘覆盖，**所有连续位置**都至少落在九站中的一个保证接收盘内。实际结束时，`covers_arena` 还对**已经完成扫描**的站位逐圆弧检验；计划上有九站不等于可以跳过扫描。全向、半径不小于 1000 m、每个未知频道在对应站位被测过，才允许把未发现频道改为 `ABSENT`。

**课内应用 5.5-A 与解答。** 若把环半径擅自改成 3000 m，能否仅凭“八站仍围着圆”宣称覆盖？不能。取目标边界上方位恰在两个环站中间的 $g$，即 $r=1800$、$\phi=\pi/8$，有 $\|g-s_k\|^2=1800^2+3000^2-2(1800)(3000)\cos(\pi/8)>999^2$；中心站也距它 1800 m，故这个点未覆盖。此题训练的是“构造一个反例位置并代入不等式”，站数不变不能代替半径证明。

### 应用 B：Q3 怎样决定是否绕路

`Strategy._choose`（454 行）比较下一站 `next_site` 与已发现频道。程序采用

$$
\text{score}=d(p,c_i)+d(c_i,s)-d(p,s)+1.0r_i,
$$

其中 $c_i$ 是候选区域圆心，$r_i$ 是其包围圆半径。仅当分数不超过 `insert_m`（默认 600 m）才插入服务。这里的 $r_i$ 是对未来服务难度的代理，不是保证还要多走 $r_i$ 米。`run`（470 行）根据新的观测在“扫下一站”和“服务某频道”之间重新选择。默认配置下 `rotate=False`、`prune=False`，保留在源码的实验分支不属于默认执行路径。

### 应用 C：Q4 的同一思想和不同前提

`source/Q4/q4_local_solver.py` 的 `coverage_route`（85 行）给出含原点、内环八点和外环十六点的站位；`_choose_insert`（179 行）用类似绕行量再加定位半径，并以 600 m 阈值决定何时服务。Q4 源有方向盲区，**全向圆盘并集不能证明其被看到**；下一课将另建定向覆盖证明。Q4 的外环站超出目标位置域是允许的，目标位置约束与设备行走范围要区分。

### 应用 D：从式 (5.4) 回到代码

逐句解释 `_choose` 中 `detour=dist(self.p,c)+dist(c,next_site)-dist(self.p,next_site)`：前两项是假设绕经候选圆心的两段行程，第三项是原本直接去下一站的行程。它回答“插入这一任务有多绕”，并不决定清除是否安全；安全证书在后续的 `mec` 和 `nearest_certified_clear` 等函数。评委若问为什么不用精确 TSP，可回答：待访任务随观测产生，目标并非事先给出的固定城市，当前规则做在线插入，并没有声称解出全局最短时间。

**应用练习。** 若 $d(p,c)=30$、$d(c,s)=40$、$d(p,s)=50$、$r_i=15$（单位均为 m），Q3 分数是多少？若改用 Q4 的不确定性权重又应到哪里看？**答案：**Q3 分数为 $30+40-50+15=35$。Q4 查看 `_choose_insert` 的实际式子，不凭 Q3 的系数推断；这份程序也使用 $+t.radius$，但要以对应源码和配置为准。

## 5.6　本章习题详解与闭卷出口

**5.1 解。** 先选 Andrea 后已有 C、C++；加入 Lisa 后又有 Ruby、Python，仍缺 Java。Ben 或 Mark 都有 Java，故至少再选一人，总人数 3。例 5.1 的 Lisa、Mark 两人是可行方案且一人方案不可能，所以多选了 1 人。此题把“贪心构造一个可行方案”与“证明最优”分开。

**5.2 解。** 从 C 出发，候选 A、B、D 的费用为 $2,13,8$，先去 A；从 A 出发未访 B、D 的费用为 $4,1$，先去 D；最后去 B 的费用为 9，再由 B 回 C 的费用为 13。全程 C–A–D–B–C，目标值 $2+1+9+13=25$。例 5.2 从 A 出发的最优巡回为 23，因此这个局部规则在该例未给出最短巡回。

**5.3 解。** 旧巡回费用 $d(A,B)+d(B,D)+d(D,A)=4+9+1=14$。按式 (5.4)，插 A–B 的增量为 $2+13-4=11$；插 B–D 为 $13+8-9=12$；插 D–A 为 $8+2-1=9$。选择第三处得到 23。枚举了给定旧巡回的全部插入边，因此只证明“固定旧顺序时增量最小”；恰好得到例 5.2 的精确最优值来自另外的穷举比较。

**5.4 解。** 仓库选择是覆盖模型：客户必须被选中仓库服务，可再在可行方案中比较成本；访问次序是路线模型。最短车辆路线可能使用更多仓库，单独优化路线也不会证明仓库数量最少。应先写各自约束，不能从一个目标的最优性推出另一个目标的最优性。

**闭卷迁移题 5.5。** 已知下一站 $s=(80,0)$，当前位置 $p=(0,0)$；频道 A 的候选圆为 $c_A=(40,30),r_A=10$，频道 B 为 $c_B=(40,0),r_B=50$，默认权重 $1$、门槛 $h=35$。求本轮动作；并说明此决定能否保证下一次测向成功、能否保证清除成功。

**详细答案。** A 的两段距离各为 50，原路为 80，绕行 20，评分 $H_A=20+10=30$。B 的两段距离各为 40，绕行 0，评分 $H_B=0+50=50$。选最小的 A，且 $30\le35$，故本轮先服务 A。**下一次测向**能否接收要另验证整块候选集离新测点的最远距离不超过接收保证半径；**清除**要另验证候选集的包围圆半径及行动点余量。评分只决定服务顺序，对这两项均无保证。若 B 的 $r_B$ 改为 5，则本轮评分 B 为 5，选择 B；这说明“顺路”与“不确定性”是两项不同的比较。

**回到源码的核对表。** `source/Q3/q3_local_solver.py:454–468` 中，`found` 是 $\mathcal J_t$ 的可服务子集；`next_site` 是 $s_t$；`detour` 是式 (5.4) 的代入；`score=detour+1.0*r` 是式 (5.7) 的特化；`insert_m=600` 是阈值；`None` 表示继续巡查。`run:470–498` 在服务或巡查后重新计算，不预先求完整 TSP。`source/Q4/q4_local_solver.py:179–186` 也以类似评分排序，但其定位可行性由定向观察章证明，不可借用 Q3 的全向负观测规则。

## 本课小结与阅读来源

覆盖产生“选哪些站位”的可行性问题；TSP 产生“既定地点走什么次序”的最优性问题；在线插入产生“任务逐渐出现时何时绕路”的决策规则。三者的保证等级不同。经典技能表、四点费用表与插入算法分类来自本课所链公开资料，正文解释与 B 题迁移自行写成；不要把本题策略误称为原书算法的逐字实现。
